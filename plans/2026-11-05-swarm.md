# Swarm Mission Implementation Plan

**Goal:** Add `/swarm` as `/goal` planning followed by bounded, dependency-aware native-agent execution and lead verification.

**Architecture:** Extend the existing mission snapshot with a swarm execution mode. A deferred native tool validates a versioned task DAG, schedules ready nodes through the existing `agent` tool, and returns durable job/artifact evidence. The lead owns planning, integration, and final verification; workers never widen authority or complete the mission.

**Spec:** `../research/ai-swarms-and-shadow-swarm.md`

## Tasks

- [ ] Test and implement mission mode, command catalog, and dispatch in both renderers.
- [ ] Test and implement DAG validation: unique IDs, dependencies, acyclic graph, worker roles, width bounds, and valid isolation.
- [ ] Test and implement scheduling: all ready tasks start, bounded by native concurrency; failure blocks descendants; cancellation and partial results are explicit.
- [ ] Wire the native tool through the existing agent execution and budget/permission path; persist mode in session mission snapshots.
- [ ] Document command behavior and limitations; run focused tests, full test suite, typecheck, lint, and build.
- [ ] Independent review and final verification.

## Constraints

- No new runtime, provider path, dependency, or permission bypass.
- Reuse `/goal` approval flow, native jobs, worktrees, agent concurrency, and parent budgets.
- No nested swarm fan-out and no dependent writer launch before predecessor integration in v1.
- Agent completion is not verification; final mission completion remains lead-owned.
- Existing planning behavior is unchanged; swarm uses the same plan approval flow.
